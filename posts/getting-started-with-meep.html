Getting Started with MEEP: Your First FDTD Simulation

A practical walkthrough of installing MEEP and writing a minimal Python script to simulate light propagating through a dielectric waveguide.

MEEP (MIT Electromagnetic Equation Propagation) is a free, open-source finite-difference time-domain (FDTD) simulation package for modeling electromagnetic systems. It's the tool I reach for most often when prototyping nanophotonic structures before fabrication. This post covers installation and a first working simulation — a straight dielectric waveguide — so you can confirm your environment is set up correctly before moving on to more complex geometries.

1. Installation

The easiest path is through Conda, which handles MEEP's compiled dependencies (MPI, HDF5, libctl) for you: 

conda create -n meep -c conda-forge pymeep pymeep-extras
conda activate meep

Verify the install by importing it in Python: 

python -c "import meep as mp; print(mp.__version__)"

2. The Simulation Model

MEEP simulations are built from a few core objects:

  • Simulation — the overall cell, resolution, and boundary conditions
  • Geometry — a list of Block, Cylinder, etc. objects with assigned materials
  • Source — where and how energy is injected (e.g. a ContinuousSource or GaussianSource)
  • PML — perfectly matched layers that absorb outgoing waves at the cell boundary

3. A Minimal Waveguide Script

Here's a complete script that launches a Gaussian pulse down a silicon (n ≈ 3.4) waveguide surrounded by air, and records a field snapshot: 

import meep as mp

cell = mp.Vector3(16, 8, 0)

geometry = [
    mp.Block(
        mp.Vector3(mp.inf, 1, mp.inf),
        center=mp.Vector3(0, 0),
        material=mp.Medium(epsilon=11.56),  # n ~ 3.4 (silicon)
    )
]

sources = [
    mp.Source(
        mp.GaussianSource(frequency=0.15, fwidth=0.1),
        component=mp.Ez,
        center=mp.Vector3(-7, 0),
    )
]

pml_layers = [mp.PML(1.0)]

sim = mp.Simulation(
    cell_size=cell,
    boundary_layers=pml_layers,
    geometry=geometry,
    sources=sources,
    resolution=20,
)

sim.run(
    mp.at_beginning(mp.output_epsilon),
    mp.to_appended("ez", mp.at_every(0.6, mp.output_efield_z)),
    until=200,
)

Run it with: 

python waveguide.py

This produces an HDF5 file (waveguide-ez.h5) containing the Ez field over time, plus a snapshot of the permittivity (waveguide-eps-000000.00.h5) so you can confirm the geometry matches what you intended.

4. Visualizing the Output

MEEP ships with h5utils for quick visualization from the command line: 

h5topng -t 0:99 -R -Zc dkbluered waveguide-ez.h5

This renders each timestep of the field as a PNG, which you can stitch into a GIF to watch the pulse propagate down the waveguide. Alternatively, load the HDF5 output directly in Python with h5py and plot with matplotlib if you want more control over styling.

A common early mistake is setting the resolution too low relative to the wavelength — MEEP works in dimensionless units, so keep in mind that resolution is in pixels per unit distance, and you generally want at least 8–10 pixels per wavelength in the highest-index material to avoid numerical dispersion artifacts.

5. Next Steps

From here, natural extensions are: adding a bend or splitter to the waveguide, computing transmission/reflection via mp.FluxRegion and get_fluxes, or moving to a fully 3D cell for structures like ring resonators or photonic crystal cavities. I'll cover flux-based transmission spectra and mode decomposition in a follow-up post.
